An ETag lets your client validate a stored response, but that validation still sends a request.

The server supplies an ETag with the JSON response. On a later conditional GET, the client sends that value in If-None-Match. If the tag matches the selected representation, an otherwise successful GET returns 304 Not Modified with no response body, allowing the client to reuse its stored body. If it does not match, a successful GET returns 200 OK with the current JSON.

To allow reuse without validation, configure an appropriate freshness policy, such as Cache-Control: max-age=60, subject to the other caching rules. The cached response can then be reused while fresh. This does not guarantee that the underlying data will remain unchanged for 60 seconds.
