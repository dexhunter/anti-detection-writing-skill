The server includes an ETag with its JSON response so the client can validate a stored copy: on a later conditional GET, the client sends that tag in If-None-Match. For an otherwise successful GET, a tag matching the selected representation leads to 304 Not Modified with no response body, so the client reuses its stored body; a nonmatching tag leads to 200 OK with the current JSON.

That saves downloading an unchanged body, but validation still sends a request. To allow reuse without validation, configure a freshness policy such as Cache-Control: max-age=60, subject to the other caching rules. The client can then reuse the cached response while it is fresh. This permission does not guarantee that the underlying data stays unchanged for 60 seconds.
