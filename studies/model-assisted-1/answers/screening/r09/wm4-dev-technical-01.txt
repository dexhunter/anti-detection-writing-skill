ETag enables receiving applications to validate whether cached representations may be reused. A server sends an ETag with the JSON response and the client includes that tag value in the If-None-Match header for future conditional GET requests. If the cached ETag matches the selected representation, the server returns 304 Not Modified with no response body, allowing the client to reuse its cached body. If the ETag does not match, an otherwise successful GET returns 200 OK with the current JSON. Still this includes sending a request. An application may employ a freshness policy such as Cache-Control: max-age=60, in which case it may reuse the response while fresh without validation, subject to other caching rules. However reuse according to this is not a guarantee that the underlying data will remain unchanged for 60 seconds.
