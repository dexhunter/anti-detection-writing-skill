Use an ETag to check whether the client can reuse its stored JSON response. The server includes the tag with its response; on a later conditional GET, the client sends that value in If-None-Match. In the ordinary successful GET case, a match with the selected representation returns 304 Not Modified with no response body, so the client can reuse its stored body. A nonmatching tag instead returns 200 OK with the current JSON.

That validation still sends a request. To allow reuse without validation, set an appropriate freshness policy, for example Cache-Control: max-age=60. Subject to the other caching rules, the client can reuse the cached response while it is fresh. This permits reuse; it does not guarantee that the underlying data stays unchanged for 60 seconds.
