Use ETag to validate a stored response on GET. The server supplies an ETag with the initial JSON response; the client sends that value in If-None-Match on a later conditional GET. For an otherwise successful GET, a validator matching the selected representation yields 304 Not Modified with no body, allowing reuse of the stored body. If it does not match, a successful GET returns 200 OK with the current JSON. This validation still requires a request.

An appropriate freshness policy, such as `Cache-Control: max-age=60`, can allow a cached response to be reused without validation while it remains fresh, subject to other caching rules, including any validation requirement. The 60 seconds permit reuse; they do not guarantee that the underlying origin data stays unchanged during that interval.
