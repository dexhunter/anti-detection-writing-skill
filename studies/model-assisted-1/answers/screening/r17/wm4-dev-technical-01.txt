An ETag lets the client validate a stored response; it does not eliminate the validation request.

The server supplies an ETag with the JSON response. To validate the stored response later, the client sends a conditional GET with that tag in If-None-Match. For an otherwise successful GET, a tag matching the selected representation produces 304 Not Modified with no response body, so the client can reuse its stored body. A nonmatching tag results in 200 OK with the current JSON.

To allow reuse without validation, configure an appropriate freshness policy, such as Cache-Control: max-age=60. Subject to the other caching rules, the client can reuse the cached response while fresh without contacting the origin server. This permits reuse; it does not guarantee that the underlying data stays unchanged for 60 seconds.
