An ETag lets the client validate a stored response and avoid downloading the same JSON again. It does not eliminate the validation request.

For an ordinary successful GET, the server supplies an ETag with the JSON response. To validate that stored response later, the client sends a conditional GET with the tag in If-None-Match. If the tag matches the selected representation, the server returns 304 Not Modified with no response body. So the client can reuse its stored body. If the tag does not match, the successful GET returns 200 OK with the current JSON.

To allow reuse without a validation request, set an appropriate freshness policy, such as Cache-Control: max-age=60. Subject to the other caching rules, the client can reuse the response while it is fresh. Those 60 seconds permit reuse; they do not guarantee that the underlying data stays unchanged.
