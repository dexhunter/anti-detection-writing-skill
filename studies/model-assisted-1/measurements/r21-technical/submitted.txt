An ETag lets the client validate a stored response and reuse its stored body, but that validation still requires a request.

The server supplies an ETag with the JSON response. In a later conditional GET, the client sends that value in If-None-Match. For an otherwise successful GET, a tag matching the selected representation produces 304 Not Modified without a response body, so the client can reuse its stored body; a nonmatching tag produces 200 OK with the current JSON.

To permit reuse without validation, configure an appropriate freshness policy, such as Cache-Control: max-age=60, subject to the other caching rules. The cached response can then be reused while fresh. This does not guarantee that the underlying data stays unchanged for 60 seconds.
