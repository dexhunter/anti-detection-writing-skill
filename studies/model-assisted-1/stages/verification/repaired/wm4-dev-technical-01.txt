ETag enables receiving applications to validate whether cached representations may be reused. A server sends ETag with the JSON response and the client includes that tag value in the If-None-Match header for future conditional GET requests. If the cached ETag matches the selected representation, the client can reuse the cached body and the server returns 304 Not Modified, with no response body. If ETag does not match, the server returns 200 OK with the current JSON for an otherwise successful GET. Still this validation includes sending a request. An application may employ a freshness policy such as Cache-Control: max-age=60 as an example, in which case the cached response can be reused while fresh without a validation request, subject to other caching rules. However reuse according to this freshness policy is not a guarantee that relevant data will remain unchanged for 60 seconds.
