an etag lets the client validate a stored response and avoid downloading an unchanged body. this validation still sends a request. the server supplies an etag with the json response; on a later conditional get, the client sends that value in if-none-match. for an otherwise successful get, a tag matching the selected representation produces 304 not modified with no response body, allowing the client to reuse its stored body. a nonmatching tag produces 200 ok with the current json. to allow reuse without validation, set an appropriate freshness policy, such as cache-control: max-age=60. subject to the other caching rules, including any validation requirements, the cached response can be reused while fresh without contacting the origin server. that permission does not guarantee the underlying data stays unchanged for 60 seconds.
