an etag lets the client validate stored json, but validation still sends a request. the server includes an etag with its response. on a later conditional get, the client sends that value in if-none-match. if the tag matches the selected representation, an otherwise successful get returns 304 not modified with no response body, allowing reuse of the stored body. if it does not match, a successful get returns 200 ok with the current json. to allow reuse without validation, set an appropriate freshness policy, such as cache-control: max-age=60, subject to the other caching rules. the client can reuse the cached response while fresh; this does not guarantee unchanged underlying data for 60 seconds.
