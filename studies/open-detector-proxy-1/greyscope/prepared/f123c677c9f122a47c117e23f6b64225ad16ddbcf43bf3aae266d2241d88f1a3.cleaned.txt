an etag lets the client validate a stored response. this validation still sends a request. the server sends an etag with the json response. on a later conditional get, the client includes that value in if-none-match. if the tag matches the selected representation, the server returns 304 not modified without a response body, so the client can reuse its stored body. if it does not match, a successful get returns 200 ok with the current json. to allow reuse without validation, configure an appropriate freshness policy, such as cache-control: max-age=60, subject to the other caching rules. the cached response can then be reused while fresh; this does not guarantee that the underlying data will remain unchanged for 60 seconds.
