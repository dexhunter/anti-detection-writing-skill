An ETag lets the client validate a stored response, saving the download when the JSON is unchanged. The server supplies an ETag with the JSON; the client sends that value in If-None-Match on a later conditional GET.

For an otherwise successful GET, a tag matching the selected representation produces 304 Not Modified with no response body, so the client can reuse its stored body. If the tag does not match, a successful GET returns 200 OK with the current JSON.

Validation still sends a request. To allow reuse without validation, configure a freshness policy such as Cache-Control: max-age=60, subject to the other caching rules. The cached response can then be reused while fresh. That permission does not guarantee the underlying data will stay unchanged for 60 seconds.
