An ETag lets the client validate a stored response, but that validation still sends a request. The server supplies the ETag with the JSON response; on a later conditional GET, the client sends that value in If-None-Match.

For an otherwise successful GET, a tag matching the selected representation produces 304 Not Modified with no response body, so the client can reuse its stored body. If the tag does not match, a successful GET returns 200 OK with the current JSON.

To allow reuse without validation, configure an appropriate freshness policy, such as Cache-Control: max-age=60, subject to the other caching rules. The cached response can be reused while fresh. That permission does not guarantee that the underlying data will remain unchanged for 60 seconds.
