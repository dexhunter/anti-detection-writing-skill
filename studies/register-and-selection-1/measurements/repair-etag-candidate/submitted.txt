An ETag lets the client validate a stored response for reuse, but that validation still requires a request. The server supplies an ETag with the JSON response; the client sends that value in If-None-Match on a later conditional GET. For an otherwise successful GET, a tag matching the selected representation produces 304 Not Modified without a response body, so the client can reuse its stored body. If the tag does not match, a successful GET returns 200 OK with the current JSON.

To allow reuse without validation, configure an appropriate freshness policy, such as Cache-Control: max-age=60, subject to the other caching rules. The cached response can be reused while fresh. This permission does not guarantee that the underlying data stays unchanged for 60 seconds.
