A request hook can sign before the request waits for a pooled connection. In HTTPX 0.28.1, the hook runs before the client hands the request to the transport; connection acquisition happens later in httpcore. Moving signing into a hook therefore does not guarantee that the timestamp is fresh when bytes reach the server.

Bound application concurrency before entering HTTPX, and use a short pool timeout so an attempt cannot wait indefinitely for an available connection. When retrying after `PoolTimeout`, create and sign a fresh attempt rather than reusing a stale signature. Retry only when the operation and request body are safe to repeat.

The [pool timeout](https://www.python-httpx.org/advanced/timeouts/#fine-tuning-the-configuration) bounds connection acquisition, not the complete interval between signing and server receipt. Connection setup, TLS and writes can add time. If the protocol needs signing strictly after pool acquisition, that requires a service-specific transport design; the public request hook alone cannot provide it. This follows the [client implementation](https://github.com/encode/httpx/blob/0.28.1/httpx/_client.py), not a reproduction of the reported high-volume 401s.
