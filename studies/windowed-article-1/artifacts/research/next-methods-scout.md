# Next-methods scout — September 9, 2026

Recommend one **fixed-window rewrite with an immutable candidate prefix**, using the existing writer. This is a feasible editorial experiment with limited evidence for coherence. There is **no sufficiently supported claim that it will lower current GPTZero confidence**. Do not load another model for this trial. The released DIPPER model provides the methodological precedent, but the proposed experiment changes its model, window definition and factual constraints substantially.

This note is a research recommendation, not authorization to change experimental gates. It used public-source reading and local inventory reading only: no model execution, generation trial, detector scan, paid call, account page, account change or sealed holdout access.

## Four primary-source records

All sources were accessed September 9, 2026. The three DIPPER records document one research project, not three independent replications.

1. **DIPPER paper, first submitted March 23, 2023; v2 October 18, 2023.** [Paper, Appendix C.1, Table 3 and Appendix C.2](https://arxiv.org/pdf/2303.13408v2). On 1,000 GPT2-XL continuations at L20, context wins 62% by RANKGEN and 58% by GPT3.5 perplexity. Three-sentence versus single-sentence paraphrasing wins 55% and 73%, respectively. These are automatic preference measures, not human readability votes or factual pass rates. The context comparison changes training too. Human semantic ratings at L20 were 63.3% at level 5 and 31.7% at level 4, permitting approximate or near equivalence. Appendix C.2 reports altered proper names and omissions. Section 4.2 truncates comparisons to equal length. Its 2023 GPTZero evidence does not predict Basic 4.9b.

2. **Author-owned DIPPER inference code, last file change April 17, 2023.** [Pinned `paraphrase_minimal.py`](https://github.com/martiansideofthemoon/ai-detection-paraphrases/blob/d23f77fce4b9ab7b1fa151f677c873324bfc627a/dipper_paraphrases/paraphrase_minimal.py); [file history](https://github.com/martiansideofthemoon/ai-detection-paraphrases/commits/main/dipper_paraphrases/paraphrase_minimal.py). The function defaults to `sent_interval=3`, places the current window inside `<sent>` markers, and appends every output to `prefix` before the next generation. This verifies an implemented sequential-context mechanism. It also normalizes whitespace and uses sentence tokenization, so copying it literally would be inappropriate for protected command lines and Markdown. A natural-language request to imitate this behavior omits DIPPER's learned control mechanism. The code was inspected, not executed.

3. **Author-owned Hugging Face model card, README history dated April 17, 2023.** [DIPPER model card](https://huggingface.co/kalpeshk2011/dipper-paraphraser-xxl); [README history](https://huggingface.co/kalpeshk2011/dipper-paraphraser-xxl/commits/main/README.md). The card identifies an 11B T5-XXL model trained on paragraph-aligned English translations of novels. Its lexical and order controls are trained behavior. The live page lists F32 weights and no supported inference provider. Technical installation prose is outside that training description, and this is not a small replacement for the existing writer. No model download, quantization, hardware adaptation or third-party Space is proposed. The low-cost trial below therefore tests an existing-writer adaptation, not these released weights.

4. **GPTZero developer report, February 13, 2026.** [Report, §§3.2, 3.4.2 and Table 1](https://arxiv.org/html/2602.13042v1). The developers explicitly include DIPPER-generated text in their augmentation pipeline and report supervised document/sentence classification. Their evaluation labels GPTZero 4.1b, whereas the local record concerns Basic 4.9b. This is direct counterevidence to treating DIPPER's historical bypass results as a fresh opportunity. It neither proves the proposed adaptation must fail nor identifies the cause of this article's 100% result. Detector outputs remain measurements with uncertainty, not ground truth about authorship.

## One concrete, low-cost trial

This specification incorporates the coordinator's stated cap of four or five sequential windows and one final independent masked comparison. Freeze it before writing or viewing any new scores.

1. Freeze the exact original article, current comparison baseline, reader/purpose, complete claim inventory and protected literals. Partition the original into four or five contiguous windows at existing paragraph boundaries, with at most approximately 160 original words per window. Keep each command, code block, list item and qualification with the explanation it belongs to. If those boundaries cannot satisfy the cap without splitting a necessary dependency, record the method as inapplicable before generation. Do not manufacture new source paragraphs to make it fit.
2. Freeze a source-supported claim assignment for each window, including dependencies on earlier windows. These assignments identify what each source passage says; they must not infer new actors or supply replacement prose. Every original passage and claim must be assigned exactly once for rewriting, with cross-window prerequisites marked explicitly.
3. Use a fresh writer context for each window, holding the writer/model settings and ordinary editorial instructions fixed. Supply the exact source window, its assigned claims and literals, the common reader/purpose, and the exact immutable candidate prefix. The prefix is context, not a source of new facts or editable content. Instruct the writer to return only one rewritten window and a separate fidelity self-check. Do not supply future prose, another arm, exemplar prose, scores or detector guidance. Any necessary forward dependency must be resolved in the frozen partition before this step.
4. Accept a window into the prefix only after its one output meets the existing literal and factual checks. “Accepted” here means provisional assembly acceptance, not independent quality approval. Preserve raw output and prompt bytes. On a material failure, stop and retain the failed run; do not regenerate, repair, select another draft or repartition adaptively. A wholly unchanged article is a no-op.
5. Assemble the windows in order with their original separators. Make no whole-article cleanup pass. Give the completed candidate and fixed baseline, with masked arm labels and no scores, to one independent reviewer alongside the original and complete claim contract. Require every fact and protected span, readable cross-window references, professional tone, and candidate preference or a tie. If the baseline is preferred or fidelity fails, retain the rejection and do not scan.
6. Only under the existing authorization and measurement limits, scan the **complete** baseline and complete candidate as a fresh GPTZero pair in the same mode/model. Freeze exact reviewed text and retain all three confidences and warnings. Never scan windows separately or omit content to change detector eligibility. A scan reduction belongs to the whole procedure on this exposed development article; it does not isolate chunking or establish generalization.

The proposed budget is four or five writer outputs, the existing inexpensive acceptance checks, and one final independent comparison. There is no new local model or paid provider. A live detector pair is conditional on the quality gates and already established measurement authorization, not authorized by this note.

## Reasons to reject or limit the proposal

The source evidence compares context-aware trained paraphrasers and short windows; it does not compare a modern instruction-following writer's full-article output with five fresh-context outputs. The 160-word paragraph windows are a declared adaptation of the released three-sentence loop. They may be too large to retain the paper's local-generation behavior, and they do not diagnose the AuthorMist failure.

The existing writer already reads surrounding text during ordinary drafting. The substantive difference here is the enforced output scope, reset between calls and immutable prior candidate—not merely “use context.” Extra calls, lost look-ahead and fixed boundaries could produce repetitive openings, stiff seams, inconsistent terminology or a prerequisite introduced too late. A factual error in a provisionally accepted prefix could also propagate. The final full-source review is necessary because per-window literal checks cannot detect all of these failures.

Proceed only as this one bounded quality experiment if the source admits a sound fixed partition. There is no basis here for another model installation, a larger search batch, a changed detector gate, or a claim that the skill now has a validated score-reduction method.
