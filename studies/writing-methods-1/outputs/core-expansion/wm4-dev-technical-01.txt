An ETag lets the client validate its stored JSON response. The server supplies the ETag with the response, and the client sends that value in If-None-Match on a later conditional GET. If the tag matches the selected representation, the server returns 304 Not Modified with no response body, so the client can reuse its stored body. If it does not match, an otherwise successful GET returns 200 OK with the current JSON.

That validation still sends a request. To permit reuse without validation while the response is fresh, configure an appropriate freshness policy, for example Cache-Control: max-age=60, subject to the other caching rules. Fresh reuse does not guarantee that the underlying data will stay unchanged for 60 seconds.
