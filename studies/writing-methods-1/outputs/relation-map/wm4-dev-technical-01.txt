An ETag lets your client validate a stored JSON response and avoid downloading the body again when it is unchanged. Validation still requires a request; the ETag alone does not eliminate it.

The server sends an ETag with the initial JSON response. On a later conditional GET, the client puts that value in If-None-Match. In the ordinary successful GET case, if the tag matches the selected representation, the server returns 304 Not Modified with no response body, and the client can reuse its stored body. If the tag does not match, the server returns 200 OK with the current JSON. See [HTTP Semantics](https://www.rfc-editor.org/rfc/rfc9110.html).

To allow reuse without validation, configure an appropriate freshness policy, for example Cache-Control: max-age=60. While the cached response is fresh, the cache can reuse it without a request if the other caching rules permit. A freshness lifetime of 60 seconds does not guarantee that the underlying data stays unchanged for that period. See [HTTP Caching](https://www.rfc-editor.org/rfc/rfc9111.html).
